## What protects the site

**Sign-in**
- Passwords are stored with Argon2id. They must be at least 12 characters, must not contain the
  person's email name, and must not be a common or easily guessed password. "Password2026!",
  "Qwerty123456", "Nairobi12345!" and all-number passwords are refused, including with letters
  swapped for numbers or symbols.
- Staff must use two-step login (authenticator app). The secrets are encrypted at rest.
- An account locks for 15 minutes after 5 failed attempts. Requests to sign-in and other
  sensitive endpoints are rate-limited.
- Sessions are kept on the server and identified by an HttpOnly cookie. Staff are signed out
  after 15 idle minutes. Sessions expire after 12 hours regardless of activity.
- Every form that changes data is protected against cross-site request forgery.

**Permissions**
- Every admin action checks a named permission.
- Roles can be limited to one section of the site.
- Applicants can only ever see their own application.

**Audit log**
- The audit log is at Admin → Audit log (super administrators only).
- It records sign-ins, failed and blocked sign-ins, wrong two-step codes, account lockouts,
  password changes and resets, and every change made in the admin: pages, menus, text, settings,
  media, users, roles and applications.
- It can be filtered by type, action, person, item, IP address and date.

**Content**
- Rich text is cleaned on the server before it is saved.
- Uploads are checked by their real file type, images are re-encoded, and file names are
  generated by the system.
- Applicant documents are private. They are never served from the public `/media` folder.

**Browser protections**
- Content-Security-Policy:
  - Scripts only run from the site itself, or when they carry a fresh per-request nonce, or
    when they match the hash of a script known at build time.
  - Only YouTube, Vimeo and OpenStreetMap may be embedded.
  - The site cannot be framed by other sites.
- Also set: HSTS (production), Referrer-Policy, Permissions-Policy (camera, microphone,
  location and payment are off), and nosniff.
- The server-side renderer only answers for approved host names (`NG_ALLOWED_HOSTS`).

**Going live safely**
- With `NODE_ENV=production` the API refuses to start if:
  - cookies are not HTTPS-only;
  - staff two-step login is off;
  - a secret is missing or short;
  - the database looks like the training one, or uses `root`;
  - the website address is not `https://`.
- See README "Going live".

**Backups**
- `npm run backup` saves the database and all uploaded files with checksums.
- `npm run backup:check` restores the newest backup into a separate scratch database and
  confirms every table, row and file came back.

## Accepted risks

| Item | Why it is accepted | Review |
|---|---|---|
| Quill 2.0.3 rich-text editor: low-severity advisory GHSA-v3m3-f69x-jf25 (no fixed version yet) | The editor is only used inside the staff admin. Its output is cleaned by sanitize-html on the server and by Angular in the browser, and the CSP blocks injected scripts. | Upgrade when Quill releases a fix. |
| `style-src 'unsafe-inline'` in the CSP | Angular adds component styles at run time. Inline styles cannot run code, and scripts stay locked down. | Revisit if Angular adds style nonces for all cases. |
| Email and SMS paused | Applicants see every update on their status page. No messages leave the system. | Turn on when a provider is chosen. |
| M-Pesa STK Push paused | Staff confirm fee codes by hand. Each confirmation is audit-logged. | Turn on with Daraja production keys. |

## Still to do before launch (steps 14–15)

- Production database: separate server or instance, encrypted disk, TLS, a dedicated least-privilege
  user, and no public network access (blueprint section 13).
- Real HTTPS certificate on the live domain, with HSTS (already on in production mode).
- Run `npm run backup` nightly (cron or Windows Task Scheduler), and copy the `backups` folder to a
  second location. Run `npm run backup:check` at least once a month.
- Change the super administrator's password and confirm each staff member has two-step login.
- A penetration test or independent review once the site is on the staging server.
